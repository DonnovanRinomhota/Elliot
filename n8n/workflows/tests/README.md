# Workflow Logic Tests

n8n Code node logic extracted and tested standalone with plain `node`, since n8n workflows can't be unit tested in place. Run them all with `npm ci && npm test` in this folder (GitHub runs this on every pull request), or one file with `node <filename>.js`.

The SQL inside the workflows is checked separately, against the database the migrations build: `db/test/check_workflow_sql.py` plans every query, and `db/test/journeys.py` runs the real queries through the seven customer journeys (both run by `db/test/run.sh`).

- `chunking_logic.test.js` — tests the paragraph-based chunking algorithm used in `08-knowledge-ingestion.json`'s "Chunk Text" node. Covers: normal multi-paragraph text, empty input, a single short paragraph, and a known limitation (a single long paragraph with no blank-line breaks doesn't get split and produces an oversized chunk — see `docs/workflow-specs/08-knowledge-ingestion.md` for the fix path if this becomes a real problem).

When you change a Code node's logic in one of the workflow JSON files, update the matching test here and re-run it before re-exporting/re-importing into n8n — catching a logic bug this way is much faster than debugging it through n8n's UI node by node.
- `listings_inbox_summary.test.js` — same approach, for the November 2026 additions: workflow 01's takeover check, `search_listings` tool (definition, allow-list, routing, result text), token-usage accumulation through the tool loop and the *Log AI Usage* node; workflow 10 sending hot leads through 24; workflow 24's recipients and email; workflow 31's daily summary email.
- `client_ready_fixes.test.js` — reads the Code-node source straight out of the workflow JSON (no copies to drift) and runs it with a small stand-in for n8n's runtime. Covers the internal-webhook secret gate (19/21/22/30, and that all four are identical), the Meta signature check in 25 (valid, tampered, wrong secret, malformed, missing header, no secret, opt-out), workflow 30's cancel decisions and calendar-result mapping, and that workflow 10's scoring only produces statuses `leads_status_check` allows.
- `appointment_listing.test.js` — viewings linked to a property and an agent (0030): `book_appointment`'s optional `listing_id` (definition, wiring to 12, `tool_schemas.json` in sync), the listing id in `search_listings` results, workflow 12's lookup parameters, the Google Calendar event (property, address, agent as guest; notes with quotes stay valid JSON), the insert parameters and the booking result.
- `chat_contacts.test.js` — 0031: visitor messages saved once (01's *Log User Message* runs once, not per history row), website chats gated on name + email/phone (*Identify Visitor* → *Visitor Identified?* → *Respond: Ask For Details*), the visitor block in Elliot's prompt, the shared contact function in 10 / 16 / 25 (no more `ON CONFLICT` on the partial unique indexes), the email sender's display name, and drafts in 14 / 26 greeting by name or asking for it.
